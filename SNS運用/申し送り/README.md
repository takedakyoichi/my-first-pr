# 申し送り

**オーナーが決めたことを、社員に確実に渡すための箱。**

## なぜあるか

**2026-08-24、決まった指示が2件、社員に渡らないまま消えかけた。**

- リアクションをくれた人をフォローする運用（新設）
- 公開済みnote記事のタイトル差し替え

どちらも**会話の中では合意していたが、社員が読む場所には何も書いていなかった。**
オーナーの「noteの修正も認識してくれてる？」で発覚した。

**渡す経路が `引き継ぎノート.md` しか無く、そこは SNS担当が窓の終わりに書き換えるファイルだった。**
**窓が動いている間は、こちらから書けない。** 待っているうちに忘れる。

## 仕組み

**1つの指示 = 1つのファイル。** 共有ファイルを書き換えないので、**窓の稼働中でも置ける。**

```
申し送り/
  2026-08-24-2150-リアクションフォロー.md   ← 未処理
  2026-08-24-2150-note記事タイトル差し替え.md ← 未処理
  済/
    2026-08-24-1900-○○.md                   ← 完了したらここへ移す
```

## 書く人・読む人

| **書く** | **メインセッションだけ。** オーナーの決定を受けた時点で、すぐ1ファイル作る |
|---|---|
| **読む** | **全社員。起動したら必ず `申し送り/` の中身を全部読む**（`済/` は読まなくてよい） |
| **消す** | **消さない。** 完了したら**末尾に完了記録を書いて `済/` へ移す** |

## ファイルの形

```markdown
# （1行で、何をするか）

宛先: SNS担当 / 分析担当 / 執筆担当
出た日時: 2026-08-24 21:50
期限: 22:00窓 /「次の窓」/「急がない」
優先度: 最優先 / 通常

## やること
（手順。社員がこれだけ読んで動ける粒度で）

## 判断の理由
（**オーナーがなぜそう決めたかを書く。** 理由が無いと、社員は実行時に安全側へ倒して勝手に変える。
 実例: 「量が多くないから22時で全部」を書かないと、社員は「数日に分ける」と自己判断する）

## 完了記録（実行した社員が書く）
- 実施日時 / 結果 / 落とした項目とその理由
```

## 指示と注意書きを、同じ紙に並べない（2026-08-24 実際に失敗した）

**22:00窓に「見出しを9本→6本にする」という表を渡したのに、実行されなかった。**
**同じ紙に「差分を欠落と決めつけるな。オーナーが直接編集している」と書いていたため、
担当は指示された変更を「オーナーの編集」と解釈し、報告だけして終わった。**

**注意書きが、指示を打ち消した。**

→ **1つの申し送りには、1つの指示だけを書く。**
→ **注意書きを添えるなら、「この指示には当てはまらない」と明記する。**
→ **「これは指示です。差分の報告ではありません」と冒頭に書く**のが確実。

## やらないこと

- **未処理を1つにまとめない。** まとめると、片方だけ済んだときに状態が書けなくなる
- **`済/` に移さず消さない。** 何を渡して何が済んだかが追えなくなる
- **社員がここに新しい指示を書かない。** 気づきは `手順メモ-○○.md`、提案は `改善提案.md`
