# 株式自動売買bot 設計書

作成日: 2026-07-05

## 1. 概要

米国株を対象に、ルールベースの短期戦略で自動売買する bot を作る。
まずは **ペーパートレード（仮想資金）で完結**させ、成績を検証できる状態をゴールとする。
本番口座への接続は本設計のスコープ外（将来、別途ユーザー承認のうえで判断）。

### ゴール（このスコープの完了条件）
- ペーパー口座で 5 分足のルールベース戦略が自律的に売買し続ける
- 売買・損益がログと Slack に残り、翌朝に成績を確認できる
- 過去データによるバックテストで戦略の成績を数字で検証できる

### 非ゴール（やらないこと / YAGNI）
- 本番（実資金）での発注
- 空売り（ショート）
- ミリ秒を争う高頻度取引（HFT）
- 複数戦略のプラグイン基盤（将来拡張として設計だけ意識、実装しない）
- クラウド常時稼働（まずローカル Mac 夜間稼働。後日移行は視野）

## 2. 前提・決定事項

| 項目 | 決定 |
|---|---|
| 市場・API | 米国株 × Alpaca（公式 API、`alpaca-py` SDK） |
| 資金 | ペーパートレード（仮想資金）のみ |
| 戦略 | ルールベース（EMA クロス順張り・買いのみ） |
| 判断間隔 | 5 分足、短期（数分〜数時間保有、日をまたがない） |
| 稼働 | ローカル Mac、米国市場時間中（日本時間の深夜〜早朝）に稼働 |
| 通知 | ログファイル ＋ Slack（Incoming Webhook） |
| 言語 | Python |

### データに関する注意
Alpaca 無料データは取引所が一部（IEX）に限られる。ペーパー検証には十分。
本番・高頻度化する場合は有料データが必要になりうる（今回はスコープ外）。

### 認証情報の扱い
Alpaca API キー / シークレット、Slack Webhook URL は **環境変数**（または `.env`、gitignore 対象）で管理し、コードにハードコードしない。

## 3. アーキテクチャ

責務ごとにモジュールを分割。各モジュールは単体でテスト可能にする。
最重要方針: **`strategy.py` は「バー → シグナル」の純粋関数**にし、
本番ループ（`run_live.py`）とバックテスト（`backtest.py`）で同じ頭脳を使い回す。

```
株自動売買bot/
├── config.py          … 銘柄リスト・戦略/リスクのパラメータ・認証情報の参照
├── data.py            … Alpaca から 5 分足を取得（本番/バックテスト共通の取得層）
├── strategy.py        … バー → 売買シグナル（純粋関数・頭脳）
├── risk.py            … 発注サイズ・保有数上限・損切り/日次損失の判定
├── broker.py          … Alpaca へ発注（ペーパー）・保有/口座状況の取得
├── notifier.py        … Slack 通知
├── journal.py         … 売買ログ ＋ 損益サマリー
├── backtest.py        … 過去データで strategy を再生し成績を出力
├── run_live.py        … 市場時間中に 5 分ごとに回すメインループ
└── tests/             … 各モジュールの単体テスト（fixtures 含む）
```

### データフロー（本番ループ 1 サイクル）
1. `run_live.py` が市場オープン中か判定（`broker`/Alpaca の時計・カレンダー）
2. `data.py` が対象銘柄の最新 5 分足を取得
3. `strategy.py` が現在の保有状況を受け取り、銘柄ごとに `BUY` / `SELL` / `HOLD` を返す
4. `risk.py` が発注可否とサイズを決定（現金・保有数・上限・日次損失をチェック）
5. `broker.py` が Alpaca（ペーパー）へ発注
6. `notifier.py` が Slack へ通知、`journal.py` が記録
7. クローズ 15 分前になったら全ポジションを手仕舞い

## 4. 各モジュール仕様

### config.py
- 対象銘柄リスト（流動性の高い米国大型株を 10〜20 銘柄に限定。初期値例: AAPL, MSFT, NVDA, AMZN, GOOGL 等）
- 戦略パラメータ: 短期 EMA 本数（初期 9）、長期 EMA 本数（初期 21）、モメンタム判定
- リスクパラメータ: 同時保有数上限（初期 5）、1 銘柄あたり資金割合（初期 10%）、
  損切り（初期 −2%）、利確（初期 +4%）、日次最大損失（初期 −5%）
- 手仕舞い: クローズ前 15 分でフラット化
- 認証情報は環境変数から読む（ここには書かない）

### data.py
- Alpaca から指定銘柄・期間の 5 分足バーを取得
- 本番（直近バー）とバックテスト（過去期間一括）の両方に使える取得インターフェース
- 取得失敗時は例外を投げ、呼び出し側でリトライ/停止判断

### strategy.py（頭脳・純粋関数）
- 入力: 銘柄ごとの 5 分足系列 ＋ 現在の保有状況 ＋ config パラメータ
- 出力: 銘柄ごとの `BUY` / `SELL` / `HOLD`
- エントリー（買い）: 短期 EMA が長期 EMA を上抜け かつ モメンタムがプラス
- エグジット（売り）: 短期 EMA が長期 EMA を下抜け / 損切り到達 / 利確到達 /
  クローズ前フラット化
- 副作用なし（発注・IO をしない）。ゆえにテストとバックテストが容易

### risk.py
- 発注サイズ算出（総資産 × 割合 / 現在価格）
- 同時保有数上限のチェック
- 現金残高のチェック
- 1 銘柄ごとの損切りライン到達判定
- 日次最大損失に達したらその日の新規売買を停止

### broker.py
- Alpaca 取引 API のラッパ（ペーパー環境固定）
- 成行/指値発注、保有ポジション取得、口座残高取得、市場オープン判定
- ペーパー/本番の切り替えは設定で明示（デフォルト ペーパー）

### notifier.py
- Slack Incoming Webhook へメッセージ送信
- 送る内容: 売買実行（銘柄・数量・価格）、日次サマリー、致命的エラーのアラート
- Slack 送信失敗が bot 本体を止めないよう分離（通知はベストエフォート）

### journal.py
- 売買履歴の記録（CSV もしくは軽量 DB）
- 日次の損益サマリー算出（実現損益・保有評価損益・売買回数・勝率）

### backtest.py
- Alpaca の過去 5 分足を取得し、`strategy.py` をそのまま再生
- 出力指標: 総リターン、勝率、最大ドローダウン、売買回数
- 戦略/パラメータ変更時の検証に使う

### run_live.py
- 市場オープン中のみ 5 分間隔で 1 サイクルを実行
- 通信断・API エラーはリトライ、致命的なら Slack アラートして安全停止
- クローズ 15 分前に全ポジション手仕舞い

## 5. エラーハンドリング方針
- API エラー: 一時的なものはリトライ（指数バックオフ）、継続不能なら安全停止＋Slack アラート
- 発注前チェック（現金・保有数・上限）で不正な注文を未然に防ぐ
- 例外を握りつぶさない。想定外は必ずログ＋通知に残す
- 通知（Slack）の失敗は本体を止めない

## 6. テスト方針（TDD）
- `strategy.py`: 固定の入力バー（fixtures）でシグナルを検証（上抜け/下抜け/損切り/利確/フラット化）
- `risk.py`: サイズ算出・保有数上限・現金不足・日次損失停止の各分岐を検証
- `journal.py`: 損益サマリー計算の正しさ
- `broker.py` / `data.py`: Alpaca API はモック化して呼び出しを検証（実 API は叩かない）
- `backtest.py`: 既知の系列で成績指標が期待どおり出るか

## 7. 変更容易性（戦略は後から育てる）
- レベル 1: `config.py` のパラメータ変更のみ（EMA 本数・損切り/利確%・銘柄・保有数）
- レベル 2: `strategy.py` の中身差し替え（他モジュールは無変更）
- レベル 3（将来）: 複数戦略のプラグイン化・成績比較（今回は非実装）
- 変更後は必ず backtest で成績確認 → 良ければペーパーへ反映

## 8. 段階的な進め方（マイルストーン）
1. スケルトン＋config＋認証情報の読み込み、Alpaca 接続確認（ペーパー）
2. data.py（5 分足取得）＋テスト
3. strategy.py（EMA クロス、純粋関数）＋テスト
4. risk.py（サイズ・上限・損切り・日次損失）＋テスト
5. broker.py（ペーパー発注・保有取得、モックテスト）
6. journal.py ＋ notifier.py（記録・Slack）
7. backtest.py（過去データ再生・成績出力）
8. run_live.py（5 分ループ・市場時間・手仕舞い・エラー処理）
9. ペーパーで数日試走 → 成績レビュー
