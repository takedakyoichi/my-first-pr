# SNS運用AI社員（sns-operator）設計

作成日: 2026-08-23

## 目的

X と note の日次運用を、一人のサブエージェント（AI社員）に任せる。
オーナーの作業時間は1日10分程度で、判断が必要なものだけが上がってくる状態を作る。

## 担当範囲

| 担当する | 担当しない |
|---|---|
| 自分宛リプの返信 | note記事の執筆（オーナー取材が必要） |
| X いいね・フォロー | アイキャッチ作成 |
| note スキ・コメント | 週次分析（メインセッションが担当） |
| X 新規ポストの起案と投稿 | 有料note の価格・企画判断 |
| 伸びている人の観測と反映 | |
| 実績ログの記録 | |

## 権限

**新規ポストを含めて全部自分で実行し、日報でまとめて報告する。** 事前承認は取らない。

ただし自律性と引き換えに、後述の「精査」を必ず通す。取り返しのつかない事故（事実誤認の投稿・不適切ないいね）は、
承認ゲートではなく**精査の徹底**で防ぐ。

## ファイル構成

```
.claude/agents/sns-operator.md   社員そのもの。名前・性格・判断基準。一度書いたら基本変えない
SNS運用/運用ルール.md             可変ルール。判定基準・上限・ペルソナ・禁止事項・技術手順
SNS運用/引き継ぎノート.md          社員の業務メモ。消化状況・保留中の判断・関係の履歴
SNS運用/ベンチマーク.md            伸びている人の観測記録と、試したことの結果
SNS運用/ログ/YYYY-MM-DD.md        実績ログ。送った文面を全文記録
```

**分離の理由**: この4日で判定ロジックが3回、タイマー方式が1回、フォロー方針が1回変わった。
変わるもの（ルール）と変わらないもの（社員の人格と手順の骨格）を分けないと、
ルールを直すたびに社員を書き換えることになる。

## 社員の継続性

**社員は一人だけ。作り直さない。**

- セッション中は `SendMessage` で同じ社員に窓を投げる。文脈を保ったまま続きをやる
- 引き継ぎノートは通常運用では使わない。プロセスが途切れた場合の保険
- 復帰時はノートを読ませて再開する。立ち上がるのは「新人」ではなく「ノートを読み返した同じ社員」

**クラウドでの定期実行は使えない。** X も note もオーナーのMacのログイン済みChromeを操作して動くため、
クラウド側からは何も操作できない。ローカルのタイマーから起動する構成を維持する。

## 動作フロー（1窓ぶん）

1. 運用ルール.md を読む
2. その日のログを読む（消化済み件数＝上限管理の起点）
3. 自分宛リプを全件確認して返信
4. リアクション（X いいね／note スキ／フォロー）
5. 伸びている投稿の観測
6. 新規ポスト
7. ログに追記（送った文面は全文）
8. メインセッションに要約を返す

### 3. 自分宛リプの確認範囲

通知欄だけでは漏れる（あすちんさんのリプを1日以上見落とした実例）。以下3箇所を必ず見る。

- 通知欄（Mentions）
- 固定ツイートのリプ欄
- 自分の全ポストのリプ欄

## 誤爆防止：判断と実行を分離する

**原因**: 6件の誤爆はすべて「正規表現でフィルタしてそのまま押すループ」で発生した。
「押す」と「判断する」が同じ処理に入っていたため、判断が甘くても止まらなかった。

**正規表現の原理的限界**: 「明日口腔外科手術だから美味しいものを食べる最後の機会」は
`美味しい` を含み `病院` を含まないので必ず通る。何語追加してもこの種はすり抜ける。

### 必須の3段構成

```
1. 候補取得   候補の本文・投稿者・リンクをまとめて取得（実行はしない）
2. 足切り     明らかな販促・アフィbot・スパムを正規表現で除外
              ※「落とす」ためだけ。通ったから押してよい、にはしない
3. 精査       残った候補を1件ずつ実際に読み、押す／押さないを決める
4. 実行       通ったものだけ押す
```

**JSのループで一気に押す実装は禁止する。**

### リプに追加する2つの確認

- **スレッド全体を読んでから書く** — yosさんの投稿は前向きな内容だったが、スレッドを遡ると
  不登校と入院の背景があった。本文だけ見て軽く返していたら失礼になっていた
- **返信済みでないか確認する** — あやさんに8/20に返信済みなのに再度返信しかけた

### 取り消し手順の位置づけ

なくさないが、主たる安全装置ではなく**精査をすり抜けた場合の最後の手段**とする。
使ったら必ずログに「なぜ精査で防げなかったか」を書く。書かないと同じ穴が塞がらない。

## 投稿前チェック（機械的に実施）

この4日で実際に起きた事故だけを潰す。

| チェック | 潰す事故 | 方法 |
|---|---|---|
| 数字の残存 | 「約10万円」→「約万円」（8/23発生） | 元の文と投稿欄の数字を突き合わせる |
| 誤変換スキャン | 頼む→頑む、癖→癱、諦める→諸める、晩→晚、腑→腐（4日で5件） | 下書きをJSで読み出し、誤変換候補の正規表現で検査 |
| 事実の裏取り | 記事の記述と食い違う投稿 | 数字や主張を出すときは元記事を参照してから書く |

## 伸びている人の観測

**狙い**: フォロワー182に対し1ポスト14〜35impという現状の課題に直結させる。

### 対象の選び方

わざわざ探しに行かない。リアクション作業中に必ず伸びている投稿に出会う（8/23も4.9K表示の食洗機ネタに遭遇）。
基準は「フォロワーが多い人」ではなく**「うちと同じテーマで、うちより桁違いに伸びた投稿」**。
フォロワー数は真似できないが、投稿の作り方は真似できる。

### 見るもの

| 対象 | 見るもの | 頻度 |
|---|---|---|
| ポスト | 書き出しの型、長さ、改行、数字の使い方、締め方 | 毎日 |
| リプ | どんなリプに返信が付いているか | 毎日 |
| プロフィール | 名前の付け方、bioの構造、固定ツイート | 週1 |

プロフィールを週1にするのは、毎日見ても同じ観察を書き続けることになるため。

### 空回りさせない3つの規則

1. **明日試すことを1つだけ決める** — 複数決めると何も試さない。「書き出しを問いかけにする」のように、
   明日の投稿で実際に検証できる粒度にする
2. **試した結果を翌日記録する** — 試したポストのimpを翌日見て、効いたか書く。
   これがないと「分析した気になる」で終わる
3. **発見がない日は「なし」と書く** — 毎日やると無理に絞り出す日が来る。捻り出した観察は嘘になる

## 窓の構成（変更が必要）

現行は6窓（7:38 / 12:22 / 18:47 / 20:33 / 21:47 / 22:58）。
**「ポストを1時間に1回」はこの6窓では実現できない。** サブエージェントは呼ばれた時しか動けないため、
毎時投稿するにはタイマーを毎時に増やす必要がある。

→ **稼働時間中は毎時起動に変更する（7:00〜23:00の17回）。**
リプ・いいね・スキも17回に分散されるので、1回あたりの負荷はむしろ下がる。
23:00の回を最後に、翌7:00まで稼働しない。

## 稼働量

| 種別 | 目標 | 到達の仕方 |
|---|---|---|
| リプ | 100件/日 | **段階的に上げる**: 20→40→60→80→100。数日かけて上げ、どの水準で警告が出るか観測する |
| ポスト | 1時間に1回（7:00〜23:00で17本/日） | 段階を踏まず、数日試して質が保てるか見る |

**17回の窓への配分**（リプ100件・noteスキ60件到達時）: 1窓あたり リプ6件・ポスト1本・いいね3件・noteスキ3〜4件。
段階を上げている途中は、その日の目標件数を17で割った数を1窓の目安にする。
| X いいね | 従来どおり（50件/日目安） | |
| note スキ | **60件/日から開始** | 1件あたりのビュー返りを見て調整（下記） |

**段階的に上げる理由**: Xは絶対量だけでなく「急変」を見る。現状17件/日のアカウントが
いきなり100件やると、量そのものより変化率で引っかかる。初日で制限を食うと回復に数週間かかる。

**ポストの現実的な壁**: 1日17本はネタのストックがないと質が落ちる。
質の低いポストを量産すると engagement rate が下がり、かえって表示が減る。数日試して判断する。

### note スキの適正量は「実測の返り」で決める

noteのアルゴリズムは非公開のため、推測ではなく自前の実測で判断する。
8/22が欠測になったことで比較データが取れた。

| 期間 | noteスキ実施 | note全体ビューの増加 |
|---|---|---|
| 8/21 | 41件 | +49ビュー/日 |
| 8/21夜〜8/23昼 | 0件 | +13ビュー/日 |

差分は 41件 → 約36ビュー。**スキ1件あたり約0.9ビュー返ってくる。** 現時点でほぼ線形で、飽和の兆候はない。
なお受け取るスキの方は反応が鈍く、41件出して約8件増（比率0.19）。
**スキ返しより、プロフィール訪問を誘発する効果の方が大きい。**

**運用方針**: 60件から開始し、**「スキ1件あたりのビュー返り」を毎日計算する。**
0.9前後を維持できていれば80件、100件と上げる。0.5、0.3と落ち始めたらその手前が上限。

**測る対象は「制限に引っかかるか」ではなく「1件あたりの返りが維持できているか」。**
理由: 件数を追って読まずに押すと、相手のプロフィール訪問という行動が起きなくなり、
note側の制限より先に効果が消える。0.9という数字は「実際に記事を開いて読んでからスキ」で出たもの。

## フォローバック

**フォローされたら、プロフィールを実際に読んで判断し、問題なければ自動でフォローバックする。**

正規表現だけで済ませない。読まずに押すのは「押してから考える」の再現になる。
各窓で通知欄の「フォローされました」を確認し、候補ごとにプロフィールを開いて判断する。

**X と note の両方で実施する。** 判定基準はプラットフォームごとに置き換える。

### X でフォローバックしない条件

- bio・固定ツイートに勧誘文言：副業／稼げ／月収／不労所得／仮想通貨／FX／投資助言／DMください／LINE@
- アダルト系、裏垢系
- 投稿ゼロ、または全投稿が同じリンクの繰り返し
- フォロー数がフォロワー数の10倍以上（無差別フォロー垢の典型）
- なりすましが疑われるもの

### note でフォローバックしない条件

noteは記事が実体なので、bioではなく**記事の中身**を見る。以下は実際にnoteで遭遇したもの。

- アダルト系の記事（#一人暮らし の新着先頭にいた実例あり）
- アフィリエイトまとめの量産（「〇〇おすすめ7選」が並ぶ）
- 情報商材・稼ぐ系の有料note中心
- 記事ゼロ、またはプロフィールが空
- 企業・店舗の販促アカウント

**前提**: noteでは2026-08-19にフォロー整理を実施済み（251→131、フォロバのない120件を解除）。
「フォロバしてくれる人と繋がる」方針で動いているので、自動フォロバはその延長線上にある。

判断が割れるもの（販促と本物のコンテンツが混在等）は**保留して日報で報告**。迷ったら押さない。

### 上限

**フォローバックに上限は設けない。** フォローバックは相手が先にフォローしている関係で、
自発フォローとは挙動が異なるため、同じ枠で縛る必要がない。

| 種別 | 上限 |
|---|---|
| フォローバック（X・note とも） | **なし** |
| 自発フォロー（こちらから探して行く分） | X・note それぞれ1日10件 |

自発フォローの枠は維持する。相手が動いていないので、量が増えると無差別フォローに見えるため。

**急増日のペース配分**: バッジ取得日のように1日で数十人増えた場合、
全員その日に返さず数日に分けて返す。これは上限ではなくペース配分であり、フォロバ自体は全員に返す。

### 相互フォロー狙いの垢の扱い

**フォローバックはする。ただしリプ・いいねのリソースは使わない。**

背景: フォロワー182に対しimpが14〜35しかない原因は、フォロワーの大半が #ブルバ100 系の
相互フォロー由来で実際にはTLを読んでいないため、という仮説を立てた。
相互フォロー垢をフォロバし続けると、この問題を自分で悪化させることになる。

一方でフォロバしないとフォローを外される可能性が高く、社会的証明としてのフォロワー数を失う。

**判断（2026-08-23オーナー決定）**: 当面はフォロワー数の増加を優先する。
フォローバックはコストがほぼゼロだが、リプ・いいね・noteスキは1日の枠を消費する。
**枠の奪い合いが起きるのはリアクションの方**なので、そちらを本当に読んでくれる人に集中させる。
これは X・note 共通の方針とする。

**追跡すべき指標**: この方針が効いているかは「フォロワーが増えた分だけimpも増えているか」で判断する。
フォロワーだけ増えてimpが横ばいなら、仮説どおり読まない層が増えているだけなので方針を見直す。

## 停止条件

**警告が出た場合だけでは不十分。** Xのシャドウバン（表示制限）は無告知で来るため、
「警告」という観測可能なイベントが発生しない。impが静かに落ちるだけになる。

以下のいずれかで**その日は中断し、翌日は量を1段戻す**。

- 制限警告が出た
- いいねが弾かれる
- note でエラーが出る
- **impが直近3日平均の50%未満、これが2窓連続**
- **リプへの返信率が直近3日平均の50%未満、これが2窓連続**

閾値を「2窓連続」にするのは、フォロワー182・1ポスト14〜35impという母数では
単発のブレが大きく、1回の低下では判定できないため。

中断したら日報で報告する。

## 検証

初回は1窓ぶんメインセッションが立ち会い、送った文面・押したいいね・フォロー先をすべて確認する。
判定が意図どおり効いているかを見てから通常運用に移す。

継続的な指標は**誤爆件数と誤変換件数をゼロに保てているか**。ログに記録されるので日報で追える。

## やらないこと

- クレジットカード紹介のアフィリエイト（本業との利益相反・就業規則リスク。2026-08-19にオーナーが決定）
- 「スキ返しお願いします」系の営業コメント
- 記事を読まないスキ連打
- 無差別フォロー（自発フォローは1日10件を上限とする。フォローバックは対象外）
- 23:00の回を最後に、翌7:00まで稼働しない
